# HomeFleet v0.6.4 — Check for updates

**The dashboard has a Check for updates button.** The "⬆ available" badge comes from a release lookup the daemon caches for 6 hours, so a release published just after a lookup stayed invisible for hours. On 2026-11-03, v0.6.3 didn't show up for that reason. The button asks GitHub right away.

## What's new
- **Check for updates**, in the dashboard header. It calls the existing uncached `GET /control/upgrade/check` (the same lookup as `homefleet upgrade --check`) and shows the answer next to the button: "⬆ 0.6.5 available", "Up to date (latest release: …)", or "Check failed: …" with the reason.
- **An explicit check refreshes the badge.** Any `GET /control/upgrade/check`, from the button or the CLI, now stores its answer behind the badge. The badge and **Upgrade all** appear on the very next poll, instead of after the cache expires.
- **Clearer failure banners.** When a dashboard request fails, the message now includes the daemon's error text, not just the HTTP status.

## Known limitations
- The button is not token-guarded: it is a GET, behind the same loopback, Host and control-header checks as the other read routes. Each click makes one GitHub API request (unauthenticated limit: 60 an hour per IP).
- Everything listed for [v0.6.3](v0.6.3.md) and earlier still applies.

## Install
On a v0.6.0+ fleet, from the dashboard: **Upgrade all**. Or, from one node:
```bash
homefleet fleet upgrade
```
On a single v0.5.0+ node:
```bash
homefleet upgrade
```
Fresh install, or from v0.4.0 or older:
```bash
npm i -g https://github.com/Hugodzl/HomeFleet/releases/download/v0.6.4/homefleet-0.6.4.tgz
```
See the [README](https://github.com/Hugodzl/HomeFleet/blob/v0.6.4/README.md#install).
