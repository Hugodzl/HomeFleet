# HomeFleet v0.2.0 — code-writing delegation

**Workers can now write code, not just read it.** v0.2 adds the `write` task kind end to end: name a repo and describe a change, a worker's local model makes the edit in an isolated throwaway worktree, the daemon commits it as `HomeFleet Worker`, and the delegating daemon fetch-applies it into *your* clone as a reviewable branch `homefleet/<jobId12>` — your own branches and working tree are never touched. Review with the exact `git diff <base>...homefleet/<id>` the tool hands back, then merge or delete.

Proven on real hardware (2026-07-15): a scoped write task delegated laptop → tower against a local Qwen3.6-35B-A3B wrote a new test file that landed and passed, end to end in ~169 s.

## What's new
- **`write` task kind** through the existing job pipeline — `WriteArtifact`/`VerifyReport` schemas, tool/wall budgets, and the `homefleet/<12-hex>` branch grammar. Protocol → **HFP 0.2.0**.
- **Git-free executor.** The agent running untrusted model output never touches git: it edits files in an ephemeral worktree, and git is a daemon-owned `finalize` op producing a single auditable `HomeFleet Worker` commit. `write_file`/`edit_file` refuse any path under `.git/`.
- **Artifacts over HFP.** The branch bundles back over the LAN transport with a three-way integrity binding (response header, bundle tip, and `JobResult.artifact.headCommit` must all agree), capped at `maxBundleBytes`.
- **The apply gate.** Landing a remote model's commits into your repo is layered — schema pin → header pre-filter → non-forced fetch under a git lockdown → an authoritative post-fetch recheck — all confined to the reserved `refs/heads/homefleet/` namespace, so even a refused apply can never move a branch you care about.
- **Config & capability.** `executors.write` is fail-closed (absent → write jobs rejected) and advertised in `NodeInfo` only when configured. An optional allowlisted `verifyCommand` runs after the commit and reports its outcome without ever failing the job.

## The theme: the gate is the feature
Every other HomeFleet capability moves *data* between machines; this one moves *authority* — it runs a model you don't control and writes the result into your repo. So the engineering that mattered was making the landing safe by construction: git-free executors, a reserved namespace, and a non-forced fetch with an authoritative recheck. Full write-up in devlog 013.

## Known limitations
- Edit application is **exact-match** — great for small, well-specified tasks; a fuzzy-replacer upgrade is planned for 0.2.1.
- Delegation operates on **committed** state; uncommitted working-tree changes aren't synced.
- v0.2 optimizes the single small-task path: no multi-commit shaping, mid-course correction, delegator-side auto-merge, or multi-worker fan-out yet.
- **Pre-alpha, Windows-first, installs from source** (no npm packages yet).
