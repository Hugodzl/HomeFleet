# HomeFleet v0.4.0 — the read-only dashboard

**See your fleet from a browser.** `homefleetd` now serves a read-only web dashboard on its loopback control port: this node's own identity and per-model catalog status, paired nodes with reachability, versions, executors, models, and load, and recent jobs in both directions — worker jobs this node ran for peers, and delegated jobs this node sent out, each with a last-seen status. `homefleet dashboard [--no-open]` prints the URL and opens it; the page polls every 3 s while visible and never issues a mutating request.

Proven on real hardware (2026-09-25): the laptop ran a checkout build while the tower stayed on v0.3.1. The dashboard listed the tower as reachable with its model `qwen3.6-35b-a3b`, and a command delegated to the tower showed up in the Delegated jobs table as `succeeded`. Hugo viewed the page and the live delegated row himself.

## What's new
- **Read-only dashboard (A1, viewing half).** `GET /` and its static assets are served by the existing loopback control server; `homefleet dashboard` opens it. `control.dashboard` (default `true`) can turn the static page off without touching the JSON routes the CLI depends on.
- **`GET /control/jobs`.** Metadata only — worker jobs and delegated jobs, never a prompt, instructions, event, or result body.
- **Delegation registry status tracking.** The delegation registry now records last-seen status from `job_status`, `job_result`, and `cancel_job`, which the dashboard's delegated-jobs table reads.
- **Security model unchanged.** Static routes are exact-match GET/HEAD only, no filesystem or path derivation; they're exempt from the `x-homefleet-control` header (a browser navigation can't set it) but stay behind the Host-header allow-list, with a strict CSP on every response. The JSON data routes still require `x-homefleet-control: 1` exactly as before.

## Known limitations
- **Job lists are in-memory** — they reset on a daemon restart.
- **Delegated status is last-seen, not live** — the dashboard poll never triggers LAN calls.
- **Delegations sent via `homefleet-mcp-stdio` aren't listed** — that shim uses its own registry.
- **Read-only** — no rename, config edits, pairing, or cancel from the page yet (that's S2 + A1, next up).
- **Same-user loopback boundary, no per-boot token** — same trust model as MCP and the CLI.
- The browser's automatic `/favicon.ico` request 403s against the static route table — console noise only, no functional effect.
- **Not on the npm registry yet** — install from the Release asset URL.
- **Pre-alpha, Windows-first.** Linux runs in CI; macOS is untested.
