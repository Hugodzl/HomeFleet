# HomeFleet v0.8.0 — release candidates

**A release can now be proven on the rig before anyone else can install it.** A `vX.Y.Z-rc.N` tag publishes the final `X.Y.Z` tarball as a GitHub prerelease that update checks and the dashboard never offer; `homefleet fleet upgrade --candidate <tag>` puts it on the fleet; and tagging `vX.Y.Z` on the last candidate's commit republishes exactly those bytes as the final release.

Real-hardware status: v0.8.0 is the first release cut as a candidate. `v0.8.0-rc.1` goes onto the rig nodes by hand, because v0.7.0 has no `--candidate`; the candidate push between nodes first runs on the next release that needs a candidate.

## What's new
- **`homefleet upgrade --candidate <tag>`** and **`homefleet fleet upgrade --candidate <tag>`** install a release candidate (`vX.Y.Z-rc.N`), or a final `vX.Y.Z` to move a node off a superseded candidate. A candidate may reinstall the same version when its tarball differs from the one running. A node already running those exact bytes prints "Already running …" and changes nothing. `--candidate` and `--to` are mutually exclusive.
- **Nodes report which bytes they run.** After each upgrade the updater records the tarball's sha256 in `installed-release.json`. `homefleet status` prints it as `releaseSha256`, the dashboard shows it in a new **Release** column, and peers see it in `NodeInfo.releaseSha256`. For a candidate, an upgrade counts as done only when the node reports the candidate's hash, and a rollback restores the previous bytes.
- **The release cache is keyed by tarball hash** (`upgrades/releases/<sha256>/`), so two builds of one version never share an entry, and a plain upgrade never mistakes a cached candidate for the final.
- **A candidate push is fetched from the pushing node only**, never from GitHub, where the candidate's bytes don't exist under the final tag.
- **Release workflow:** candidate tags publish prereleases that are never "latest"; a final tag on the last candidate's commit promotes it without rebuilding. The publishing job checks the tarball and manifest byte for byte against the candidate Release. The signing job is unchanged. See [Release candidates](https://github.com/Hugodzl/HomeFleet/blob/v0.8.0/docs/reference/releasing.md#release-candidates) and [ADR 0008](https://github.com/Hugodzl/HomeFleet/blob/v0.8.0/docs/adr/0008-release-trust-and-candidates.md).
- **HFP 0.5.0**, additive: `UpgradeRequest.candidate` and `NodeInfo.releaseSha256`. A v0.7.0 peer ignores both.

## Known limitations
- **Node 20.19+ or 22.12+ is now required** (`engines`: `^20.19.0 || >=22.12.0`), up from Node 20, because the identity certificate library moved to `@peculiar/x509` 3. Check `node -v` on every node before upgrading: `homefleet upgrade` and `homefleet fleet upgrade` don't check the Node version, so a node on an older Node installs v0.8.0 and then fails to start, and rolls back. Existing identity certificates load unchanged, with the same device IDs, so pairings are kept.
- **Hashes start out unknown.** A node that reached v0.8.0 through v0.7.0's updater (or by hand) reports `releaseSha256: unknown` until its next upgrade. Candidate installs treat an unknown hash as "reinstall allowed".
- **`--candidate` needs v0.8.0 on the node that runs it.** A v0.7.0 daemon refuses the flag, and the CLI says so.
- **After a manual `npm i -g` of the same version**, the node keeps reporting the previous hash: delete `installed-release.json` in its data directory.
- **The release cache is not pruned**, and the old `upgrades/<version>/` directories are left in place. These and the other deferred review findings are in the [backlog](https://github.com/Hugodzl/HomeFleet/blob/v0.8.0/docs/backlog.md#release-and-ci-follow-ups-from-the-2026-11-12-design).
- Everything listed for [v0.7.0](v0.7.0.md) and earlier still applies.

## Install
On a v0.6.0+ fleet, from the dashboard: **Upgrade all**. Or, from one node:
```bash
homefleet fleet upgrade
```
On a single v0.5.0+ node:
```bash
homefleet upgrade
```
Fresh install, or from v0.4.0 or older:
```bash
npm i -g https://github.com/Hugodzl/HomeFleet/releases/download/v0.8.0/homefleet-0.8.0.tgz
```
See the [README](https://github.com/Hugodzl/HomeFleet/blob/v0.8.0/README.md#install).
