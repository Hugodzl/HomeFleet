# HomeFleet v0.5.2 — upgrade the whole fleet from one command

**Fleet push: `homefleet fleet upgrade` rolls a signed release across your paired nodes.** The daemon you run it on pushes the upgrade to each peer over HFP, one at a time, peers first and itself last, and stops at the first rollback, failure or timeout. Every node still installs only a signed release, never a downgrade, and rolls back a new daemon that fails to come up.

Real-hardware status: the rig proof — 0.5.2 → 0.5.3 pushed laptop → tower with `homefleet fleet upgrade` — necessarily comes after publishing, since 0.5.2 is the first release that can receive a push. Until then the rollout, the HFP routes and the CLI are covered by unit tests and an integration test across two assembled daemons.

## What's new
- **`homefleet fleet upgrade [--to <version>] [--nodes <name|id>…] [--force-local]`** starts a rollout in the daemon (it survives the terminal closing). Peers go first, sequentially; this node goes last. A refusal (`UPGRADE_*`) or a too-old peer is reported and skipped; a rollback, failure or 3-minute timeout stops the rollout. `--force-local` applies only to this node's own final step; a busy peer is never forced.
- **HFP 0.4.0:** `POST /hfp/v0/upgrade` accepts a push and `GET /hfp/v0/upgrade/tarball/:version` serves a cached, verified tarball to a peer. Both are new optional routes, so 0.3.0 peers keep working.
- **Opt-in per peer:** `"upgrade": { "allowRemote": true }` in `config.json`. It is off by default; `homefleet setup` prints a hint while it is off.
- **`NodeInfo.lastUpgrade`** (`{ version, outcome, reason?, at }`) lets a peer's last upgrade outcome be read remotely.
- **Control API:** `POST /control/upgrade` takes `targets` (`self`, `fleet` or device IDs) and `forceLocal`; `GET /control/upgrades` reports rollout progress.

## Known limitations
- **Peers must opt in:** `"upgrade": { "allowRemote": true }` is off by default, so a peer without it refuses the push (reported and skipped).
- **Nodes on 0.5.1 or older must first reach 0.5.2 with a local `homefleet upgrade`.** Only 0.5.2+ peers accept a push; a 0.5.1 peer answers 404 and is reported as "too old". (v0.4.0 or older: `npm i -g`, see Install.)
- **Offline or unreachable peers are skipped by a default `fleet` rollout:** selection needs a reachable peer. Name them with `--nodes` to see them reported as unreachable.
- **A pushed peer downloads from the requester only when it knows the requester's address** (live discovery or known nodes); otherwise it downloads from GitHub.
- **No dashboard trigger yet, and no per-boot control token:** both are Phase 4.
- **Not on the npm registry yet**: install from the Release asset URL.
- **Pre-alpha, Windows-first.** Linux runs in CI; macOS is untested.

## Install
On a v0.5.0 or v0.5.1 node:
```bash
homefleet upgrade
```
Fresh install, or from v0.4.0 or older:
```bash
npm i -g https://github.com/Hugodzl/HomeFleet/releases/download/v0.5.2/homefleet-0.5.2.tgz
```
Once every node runs 0.5.2 and has opted in, `homefleet fleet upgrade` updates the rest. See the [README](https://github.com/Hugodzl/HomeFleet/blob/v0.5.2/README.md#install).
