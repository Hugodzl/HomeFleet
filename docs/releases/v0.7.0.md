# HomeFleet v0.7.0 — homefleet daemon

**`homefleet daemon start|stop|restart|status` runs the daemon in the background and stops it gracefully.** Until now, keeping a node running meant a long `Start-Process node "…\homefleetd.js"` line, a `Get-CimInstance` query to find the live process, and `Stop-Process`, which on Windows ends the daemon without running its shutdown.

Real-hardware status: both rig nodes upgraded 0.6.4 → 0.7.0, and `status`, `stop`, `start` through the `HomeFleet Daemon` task and `restart` worked on the laptop. From a Claude desktop shell, `status` printed the packaged-app note. Not yet checked: the commands on the tower. See [devlog 026](https://github.com/Hugodzl/HomeFleet/blob/main/devlog/2026-11-08-daemon-command.md).

## What's new
- **`homefleet daemon status`** prints whether homefleetd is running, its pid and version, the log paths and the last log line. It exits 3 when the daemon is not running. On Windows it also says whether the `HomeFleet Daemon` autostart task is registered, and prints a note when it runs inside a packaged app.
- **`homefleet daemon start`** launches homefleetd detached and waits until it answers. On Windows it runs the `HomeFleet Daemon` task when it is registered and `HOMEFLEET_DATA_DIR` is unset; otherwise it starts `node homefleetd.js` directly, with stderr in `homefleetd.err.log`. If the daemon doesn't come up, it prints the end of both logs.
- **`homefleet daemon stop [--force]`** asks the daemon to shut down and waits 30 s for it to exit. It kills the process only if its command line still names `homefleetd`, so a reused pid is never killed. If the process can't be identified, it kills nothing and exits 1.
- **`homefleet daemon restart`** is stop, then start. It doesn't start a second daemon when the stop couldn't confirm the first one is gone.
- **`POST /control/shutdown`**, a new control route, body `{ force? }`. Like the upgrade POSTs, it needs the per-boot control token, so it stays off the dashboard and can't stop a daemon of another data dir. It answers 202 `{ pid, alreadyStopping }`, or 409 `busy` (jobs running without `force`), `upgrading` (a self upgrade or fleet rollout is in progress) or `unsupported`. A repeated stop answers `alreadyStopping` and never escalates to a forced exit. While the daemon is stopping, it refuses new upgrades as `locked`.
- **`pid` in `GET /control/status`.** The daemon reports its own pid, so `status` finds the live process without a pid file that goes stale across reboots.
- No protocol change: HFP stays 0.4.0.

## Known limitations
- **`stop` needs a v0.7.0 daemon.** A v0.6.4 or older daemon has no shutdown route; `stop` says it "predates `homefleet daemon stop`". Upgrade it, or stop it by hand once.
- **The Task Scheduler path is covered only by simulated tests.** The integration test sets `HOMEFLEET_DATA_DIR`, so it never runs `schtasks`. The task is trusted by name: `start` doesn't check that it points at this install.
- **Packaged apps (MSIX).** Inside a packaged desktop app such as the Claude desktop app, Windows gives child processes a private `%LOCALAPPDATA%` and stops them when the app closes. `start` detects this and refuses unless the autostart task is registered (`--allow-packaged` overrides). The CLI there still reads the package's private copy of the config and token, so `stop` can fail with `bad-token`. Run lifecycle commands from your own terminal.
- More follow-ups are in the [backlog](https://github.com/Hugodzl/HomeFleet/blob/v0.7.0/docs/backlog.md#node-lifecycle-automation-daemon--model-server): telling this data dir's daemon from another one on the same port, polling past unexpected answers, and the strict shutdown body schema.
- Everything listed for [v0.6.4](v0.6.4.md) and earlier still applies.

## Install
On a v0.6.0+ fleet, from the dashboard: **Upgrade all**. Or, from one node:
```bash
homefleet fleet upgrade
```
On a single v0.5.0+ node:
```bash
homefleet upgrade
```
Fresh install, or from v0.4.0 or older:
```bash
npm i -g https://github.com/Hugodzl/HomeFleet/releases/download/v0.7.0/homefleet-0.7.0.tgz
```
See the [README](https://github.com/Hugodzl/HomeFleet/blob/v0.7.0/README.md#install).
