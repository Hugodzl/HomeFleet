# HomeFleet v0.6.2 — peer model status on the dashboard

**The dashboard now shows whether a peer's models are actually up.** A peer row used to list model ids only, so a tower whose daemon was reachable but whose llama-server was down looked healthy. The Models column now reads `qwen3.6-35b-a3b (unreachable)`, the same `id (status)` form `homefleet nodes` has used since v0.5.1, and turns amber when any model is not `ok`.

Real-hardware status: found on the rig on 2026-11-02, when the tower's llama-server was down after a reboot and only the CLI said so. v0.6.2 is pushed to the rig from the dashboard; see the devlog.

## What's new
- **Peer model status in the nodes table.** Each model shows its catalog status (`ok`, `unreachable` or `not_served`). Any status other than `ok` marks the cell with the warning colour. Peers older than v0.3.0 advertise no status; their model ids show alone, with no warning.

## Known limitations
- The status is the peer's own latest probe, refreshed every 60 s on the peer, so a model server that just came up can take about a minute to show `ok`.
- Everything listed for [v0.6.1](v0.6.1.md) and earlier still applies.

## Install
On a v0.6.0+ fleet, from the dashboard: **Upgrade all**. Or, from one node:
```bash
homefleet fleet upgrade
```
On a single v0.5.0+ node:
```bash
homefleet upgrade
```
Fresh install, or from v0.4.0 or older:
```bash
npm i -g https://github.com/Hugodzl/HomeFleet/releases/download/v0.6.2/homefleet-0.6.2.tgz
```
See the [README](https://github.com/Hugodzl/HomeFleet/blob/v0.6.2/README.md#install).
